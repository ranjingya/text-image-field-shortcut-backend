# 同场景多图生成与飞书回填方案

## 结论

生图后端使用现有 `POST /api/generate-image` 接口完成单张生成，无需增加多图接口，也不负责写入飞书。

业务程序负责生成编排和飞书附件回填：先生成 1 张场景锚点图，再以商品参考图和锚点图并行生成另外 4 张，最后将 5 张图片流上传到多维表附件字段。

## 职责边界

### 生图后端

- 使用 `Authorization` 访问令牌鉴权。
- 接收 JSON 图片 URL 或 `multipart/form-data` 文件流作为参考图。
- 每次请求生成 1 张图片。
- 直接返回图片二进制、MIME 类型和文件名。
- 负责模型路由、重试、兜底、并发控制和临时参考图清理。
- 参考图可使用临时 OSS 中转；临时对象在模型调用结束后删除。

### 业务程序

- 使用 Bot 身份读取多维表中的待处理记录。
- 组装平台提示词和当前图片序号要求。
- 调用生图后端生成场景锚点图和 4 张同场景图片。
- 在内存中保存生成结果，不创建永久 OSS 对象。
- 将图片流上传到目标多维表，取得 `file_token`。
- 将 5 个 `file_token` 一次性写入目标附件字段。
- 记录每行的生成、上传和回填结果，控制幂等与重试。

## 生成流程

```text
读取多维表待处理行
        ↓
商品参考图 + 第1张提示词
        ↓
调用 /api/generate-image，得到场景锚点图
        ↓
商品参考图 + 场景锚点图
        ├─ 第2张：同场景，不同机位
        ├─ 第3张：同场景，不同景别
        ├─ 第4张：同场景，商品细节
        └─ 第5张：同场景，完整展示
        ↓
5张图片全部生成成功
        ↓
逐张上传飞书素材，取得5个 file_token
        ↓
一次性写入多维表附件字段
```

第 2～5 张都直接参考第 1 张，不互相串联，避免商品和场景逐轮漂移。参考图顺序固定为“商品原图在前，场景锚点图在最后”，提示词明确说明最后一张参考图只用于约束场景。

## 生图接口调用约定

请求：

```http
POST /api/generate-image
Authorization: Bearer <access-token>
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 说明 |
|---|---|
| `requestId` | 使用多维表记录 ID 和图片序号组成追踪标识 |
| `prompt` | 完整平台提示词及当前图片要求 |
| `model` | 图片模型 ID |
| `aspectRatio` | 输出比例 |
| `imageSize` | `1K`、`2K` 或 `4K` |
| `files` | 商品参考图；第 2～5 张额外包含场景锚点图 |

成功响应：

- 响应体为单张图片二进制。
- `Content-Type` 表示图片 MIME 类型。
- `Content-Disposition` 提供文件名。
- `X-Model-Provider` 表示实际服务商。
- `X-Fallback-Used` 表示是否使用兜底服务商。

字段捷径使用的 `POST /api/process-image` 保持独立，通过 `X-Base-Signature` 和 `X-Pack-Id` 鉴权。

## 同场景提示词约束

场景锚点图负责确定空间、装修、陈设、光线、时间和色调。第 2～5 张统一增加以下约束：

```text
最后一张参考图是本批次的场景锚点图。
商品外观以商品原始参考图为准。
空间、装修、陈设、光线方向、拍摄时段和色调以场景锚点图为准。
保持同一个场景，允许机位、景别和商品摆放自然变化。
不得照抄锚点图，不得改变商品颜色、结构、图案、Logo 和配件。
```

## 飞书附件写入

业务程序直接调用飞书素材上传接口：

```text
POST /open-apis/drive/v1/medias/upload_all
parent_type = bitable_image
parent_node = <base_token>
file = <图片二进制流>
```

每张图片上传成功后取得一个 `file_token`。5 张图片全部上传成功后，通过多维表记录更新接口一次性写入附件字段：

```json
{
  "AI图片": [
    {"file_token": "token-1"},
    {"file_token": "token-2"},
    {"file_token": "token-3"},
    {"file_token": "token-4"},
    {"file_token": "token-5"}
  ]
}
```

约束：

- 使用 Bot 的 `tenant_access_token`，Bot 需要目标多维表编辑权限和素材上传权限。
- 单张不超过 20 MB 时使用完整上传；超过 20 MB 时使用素材分片上传。
- 素材上传按顺序执行，遵守 5 QPS 和每日 10,000 次限制。
- 5 张图片全部生成完成后再开始上传。
- 5 个 `file_token` 全部取得后再更新记录，避免附件字段出现半组结果。
- 已有完整附件结果的记录跳过，避免重复生成和重复写入。

## 异常处理

- 锚点图失败：终止当前记录，不生成后续图片。
- 第 2～5 张任意一张失败：只重试失败图片，成功结果保留在当前进程内存中。
- 飞书上传失败：保留图片字节并重试当前上传，不重新调用模型。
- 飞书记录更新失败：保留 5 个 `file_token` 并重试记录更新。
- 进程异常退出：下一次运行重新读取多维表状态并处理未完成记录。

## 后端改动范围

当前 `POST /api/generate-image` 已具备所需能力，第一阶段无需修改生图后端代码。需要保证部署环境满足：

- 普通程序可取得有效的 `Authorization` 访问令牌。
- 接口允许调用方提交多张参考图文件。
- 请求超时覆盖单张图片的最长生成时间。
- 临时 OSS 签名地址可被主服务商和兜底服务商访问。

同场景多图编排、飞书素材上传和附件字段更新属于业务程序实现范围。
